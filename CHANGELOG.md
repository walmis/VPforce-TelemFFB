# Changelog

All notable changes to TelemFFB are documented here. The format is loosely
based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the
project follows [SemVer](https://semver.org/) where applicable. The
`Unreleased` section accumulates changes on the current development
branch; once a build is cut, those entries move under a versioned
heading.

## [Unreleased] — Multi-Device Effect Routing

Branch: `claude/configurable-haptic-effects-V7HYh`.

A configurable routing engine that replaces the hard-coded "stick +
shaker" assumptions in the aircraft modules. Setups beyond the original
two devices — *VPForce Rudder up front + Stick on the right + bass
shaker*, *Stick + Pedals + Collective without shaker*, *dual shaker*,
and so on — are now first-class citizens. Reference docs:
[`docs/ROUTING.md`](docs/ROUTING.md).

### Added

- **EffectRouter data model** ([`telemffb/routing/`](telemffb/routing/)).
  `RouteLayer` / `EffectRoute` / `EffectRoutesPack` with selector
  grammar `id:<device_id>` / `type:<type>` / `pos:<tag>` / `both`, plus
  `DirectionPolicy` (`inherit` / `auto` / `fixed` / `from_telemetry`).
- **Device inventory** ([`telemffb/device_inventory.py`](telemffb/device_inventory.py)).
  `Device` dataclass (`device_id`, `type`, `positions`, `xy_offset`,
  `usb_pid`, `label`, `master`, `enabled`) with JSON and `config.ini`
  I/O.
- **Bundled defaults** ([`telemffb/data/effect_routes_default.json`](telemffb/data/effect_routes_default.json)).
  All 71 entries from `SHAKER_EFFECT_WHITELIST` covered, hand-tuned
  layers from the prior `shaker_effects_default.json` preserved
  byte-equal. Regenerated by [`scripts/migrate_shaker_to_routes.py`](scripts/migrate_shaker_to_routes.py).
- **Routing-aware HapticEffect facade**
  ([`telemffb/routing/ffb_router.py`](telemffb/routing/ffb_router.py)).
  Third backend alongside `ffb_rhino` and `ffb_shaker`; subclasses
  `_rhino.HapticEffect` so `isinstance` checks keep working. Activated
  in [`main.py`](main.py) via `_setup_routing` + `aircraft_base.use_router_backend()`
  after `HapticEffect.open()`. **Strict opt-in**: when no `[devices]`
  inventory is set, behaviour matches the legacy code path exactly.
- **Multi-layer FFB fan-out**. The router holds one `_rhino.HapticEffect`
  sub-handle per resolved layer, so two layers targeting the same
  device (e.g. pedals at 0° + 270° simultaneously) play in parallel.
  `start` / `stop` / `destroy` fan out across all sub-handles; each is
  named `"<effect>__layer<idx>"` for log readability.
- **Devices tab** ([`telemffb/DeviceInventoryTab.py`](telemffb/DeviceInventoryTab.py)).
  Editable table: type, position tags, optional X/Y offset (cm),
  USB PID, label, master, enabled. Auto-detect (`FFBRhino.enumerate()`),
  add / remove / clear-all. Saves on every cell change to
  `[devices].deviceInventory` in `config.ini`.
- **Effect Routing dialog** ([`telemffb/EffectRoutingDialog.py`](telemffb/EffectRoutingDialog.py)).
  Matrix view (effects × devices). Each cell: enable + gain (0–200%)
  for the first matching layer. Double-click opens the per-layer detail
  dialog (frequency factor, oscillator type, direction policy + value,
  bandpass center / bandwidth, attack / decay). Scope combo switches
  between Global routes and per-aircraft-class patches
  (`JetAircraft` / `PropellerAircraft` / `Helicopter` / etc.).
  Right-click an effect row for "Reset this effect to bundled default".
  Apply / OK saves to `effect_routes_user.json` and reloads the running
  router live (no restart for routing-only changes). Import / Export
  buttons for sharing routing packs.
- **First-run Setup Wizard** ([`telemffb/SetupWizard.py`](telemffb/SetupWizard.py)).
  Five-page `QWizard`: Welcome + Rhino scan, Device types, Position
  tags, Preset, Summary. Triggered automatically when no inventory
  exists yet (`[system].setup_wizard_done` is the dismissal flag);
  also available manually via `Help → Multi-Device Setup Wizard…`.
- **Bundled setup presets** ([`telemffb/data/setup_presets.json`](telemffb/data/setup_presets.json)):
    - *Stick + Shaker (Default)* — matches today's bundled defaults.
    - *Stick only* — silences shaker-only effects.
    - *Helicopter (Stick + Pedals + Collective)* — runway on pedals,
      rotor on stick + collective, gear on collective + pedals.
    - *Stick + Rudder front + Shaker* — forward-axis effects route
      to the rudder.
    - *Full Setup (Stick + Pedals + Collective + 2× Shaker)* — gunfire
      / CM seat-side, gear / runway pedals-side.
- **Master → Slave inventory broadcast**. New `inventory:` IPC message
  ([`telemffb/IPCNetworkThread.py`](telemffb/IPCNetworkThread.py)). Master
  saves push the JSON to all running children, which update
  `G.devices` / `G.device_positions` / the router self-cache live.
  Type / USB-PID rebinds still need a child restart (documented).
- **`docs/ROUTING.md`** — user + architecture guide.
- **CI gate**: `tests/test_routes_coverage.py` runs the migration script
  in `--check` mode and asserts every whitelisted effect has a route,
  no dead routes, no leftover legacy `route:` fields.

### Changed

- `EffectRouter` is the loader for **both** the new v4 `target:` schema
  and the legacy v1–v3 `route:` schema. `RouteLayer.from_legacy`
  converts on read; saving is always v4. Legacy `shaker_effects.json`
  files keep working without manual migration.
- `aircraft_base.py` gains `use_router_backend()` mirroring the existing
  `use_shaker_backend()`; aircraft modules themselves are **unchanged**.
  Hard-coded `direction=0/90/180` constants in
  [`telemffb/sim/aircraft_base.py`](telemffb/sim/aircraft_base.py) become
  the call-site input for `DirectionPolicy.INHERIT` and are overridable
  per layer.
- [`docs/SHAKER.md`](docs/SHAKER.md) §4.2 cross-references the new
  routing system; the Shaker audio path itself is unchanged.

### Tests

- 80 new / refreshed unit tests across
  [`tests/test_routing.py`](tests/test_routing.py),
  [`tests/test_ffb_router.py`](tests/test_ffb_router.py),
  [`tests/test_routes_coverage.py`](tests/test_routes_coverage.py).
  Pure-helper tests run in any environment; HapticEffect-facade tests
  (18) require `usb1` / `PyQt6` / `numpy` to be installed and are
  auto-skipped otherwise.
- Existing legacy tests (`tests/test_shaker_whitelist.py`) continue
  to pass — the routing engine is layered on top of the whitelist,
  not a replacement.

### Known limitations

- Type / USB-PID changes in the inventory require a child restart
  because the type binding happens once at process start
  (`main._setup_routing`). Position / label edits update live.
- `DirectionPolicy.FROM_TELEMETRY` is reserved but not implemented —
  the enum value falls through to `inherit`. A telemetry-field selector
  is planned.
- The routing-matrix UI edits the *first* layer per (effect, device)
  cell. Adding a second parallel layer on the same device is currently
  a hand-edit on `effect_routes_user.json`; the runtime engine
  supports any number, but the matrix doesn't grow extra cells yet.
